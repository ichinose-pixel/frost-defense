| -------------- | ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- | -------------------- |

ステージ1の採集報酬・建築条件・費用・敵HP/速度/ダメージ・各日の敵数は維持。後半ステージも敵HP/速度/ダメージを一律に上げない。氷の帯は地形の視覚表現で、滑り・移動制限の効果はない。防衛設備の1×4/2×2の当たり判定と出入口は全ステージ共通。

## 進行・保存

- 開始画面の3つのステージから解放済みを選択。初回はステージ1のみ。クリア後は次のステージを解放。
- 次のステージ・敗北後の再挑戦はDay1、拠点Lv1、木90/石炭36から開始。前ステージの資材・設備・ボーナスは持ち越さない。
- クリア確定時に、端末のブラウザ内へ解放段階と各ステージの直近クリア戦績を保存。演出が終わる前に閉じても解放を失わない。
- 再訪時は最新の解放済みステージを選択。過去ステージをクリアし直しても解放段階は下がらない。
- 保存する戦績は撃破数・救助数・確保拠点数・経過秒数。開始画面で選択ステージの直近戦績を確認できる。
- 途中のDay・ゲーム状態は保存しない。別ブラウザ・別端末へ同期しない。ブラウザのサイトデータ削除で記録は消える。
- 読み書きの失敗は画面に明示。保存失敗でもメモリー内で次ステージへ進める。未知の将来形式の保存データは上書きしない。

## クリア演出

最後のボスが倒れた時点で残敵は崩れて撤退。撤退分の撃破数・資源報酬は加算しない。燃料・拠点HPの更新、移動入力、飛翔体を止める。
約2.2秒で雪を弱め、夜空を明るくし、カメラが拠点を映す。その後に戦績と次ステージボタンを表示。プレイヤーの位置は動かさない。バックグラウンド・WebGL復旧待ちでは演出も停止する。
敗北したフレームではクリアを認定しない。各ステージのボスは従来同様865HP。ステージ3の最終画面は全3ステージ制覇を明記。

## 構造・検証

`src/stages.js` がステージ設定・保存・選択画面・クリア演出を担当。19ファイルをビルドで結合。v14.1の共通表示枠を維持し、プレイ中のボタンは追加しない。

`npm run check`: 30件の回帰テスト。3ステージの実際の敵撃破処理→保存→クリア演出→次ステージ、敗北リトライ、保存失敗/破損/未知形式、資源配置、描画容量、ボス数、襲撃方向を確認。
GPUを模擬したロジックテストであり、3ステージを人間が通しプレイした難易度検証ではない。実機での画面・音・長時間負荷とStage2/3の難易度は確認待ち。
